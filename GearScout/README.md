# GearScout 0.12.1

A first version of a Dalamud plugin for importing XIVGear gear sets and checking which pieces your current character owns.

## Use the compiled plugin

1. Extract `GearScout-plugin.zip` into a permanent folder. Keep `GearScout.dll` and `GearScout.json` together.
2. In FFXIV running with Dalamud, enter `/xlsettings`.
3. In **Experimental → Dev Plugin Locations**, add the full path to `GearScout.dll`.
4. Enter `/xlplugins`, open **Dev Tools → Installed Dev Plugins**, and enable **GearScout**.
5. Enter `/gearscout`, paste your XIVGear link, and click **Import**.

Example link: https://xivgear.app/sl/aadb9265-3645-45ae-8af6-3215eb26d637

To build a local set, click **New set**, enter a name, and click any slot in the editor. Search by name or ID, select a compatible piece, and click **Save set**. The job is captured when the set is created; current character level does not restrict planning. Existing local sets can be renamed or edited with **Edit set**; clicking a checklist item opens the editor at that slot. Imported sets open as independent local copies so a link refresh does not overwrite custom edits. Cancel and window close discard the draft. Empty sets can be saved.

Search is backed by local Item, EquipSlotCategory and ClassJobCategory game sheets. Results fit the set's job/slot, sort by item level, and support both ring slots. A unique ring already selected in the opposite slot is disabled. Off-hand slots may have no results for some jobs. New/changed pieces initially have unspecified materia targets; **Targets** opens a searchable materia picker with up to five entries including repeats. Local sets integrate with saved ownership and loot checks but do not equip gear or modify the game's character gearsets.

Normal sets have a **Melding planner** with exact copy/location and quality selection, editable targets (imported changes become local copies), legal bottom-first retrieval/rebuild plans, per-step success/recovery rates, stat-overcap/unknown-data flags, loose materia supply and joint 90/95/99% confidence budgets. Rates and grade restrictions come from installed MateriaGrade data; guaranteed slots, advanced permission and item-level eligibility come from the actual gear/materia rows. Saved checks retain quality and ordered melds; older checks with unknown quality require a rescan. The shopping list excludes speculative refunds and distinguishes usable bags from cached retainers. Missing/invalid gear produces an explicitly partial plan.

**Start automatic melding** processes included live pieces, automatically selects their inventory category and exact copy, opens retrieval/meld dialogs, and confirms one planned action at a time. It waits for a settled gear/stock result before advancing or retrying. Each meld request reserves an attempt before dialog opening; retries cannot exceed the session/type limits. Starting checks minimum stock and limit, and retrieval requires a free bag slot. Stop prevents future confirmations but cannot undo an already confirmed attempt. Native batch melding is not requested. Stat caps use base item/HQ stats and do not incorporate custom relic allocations.

Switch to Bard to see this example. When you switch jobs, only sets whose imported job exactly matches your active class/job appear. Bard sets do not appear on Archer. A sheet containing multiple sets imports each set; use the dropdown to switch between them. Selected-set parameters in links are passed to XIVGear's API. Reimporting the same URL refreshes its saved sets instead of duplicating them. Sets and selection are saved in Dalamud's normal plugin configuration.

For job-independent outfit planning, click **New glam set**. Slot searches show gear from all jobs, and the set appears with a **[Glam]** prefix on every job. Glam sets track appearances rather than distinct equipped copies: one owned item can fill repeated slots, including both rings, and the materia column is hidden. Saved storage and missing-loot indicators include glam targets. Regular sets keep their job/slot filters and physical-copy requirements. Glam planning does not apply plates or alter game equip restrictions.

Glam slots support lists of pieces. Click **Add gear...** in the editor, check as many search results as wanted, then **Done** and **Save set**. Search remains open for repeated selections and queries. Uncheck a result or use its individual **Remove** button to remove just that piece. Every selected piece appears in the checklist, grouped by slot with its own ownership status and location. Identical items are not duplicated within a slot; normal sets retain a single item per slot. Existing glam sets use the same saved format and can be extended without migration.

## Ownership rules

- Checks equipped items, all four inventory bags, and the Armoury Chest of the logged-in character.
- Updates approximately once per second while the window is open; login, loading and character/job changes clear the old snapshot.
- **Equipped** means a matching copy is worn by the player; **Owned** includes live bags/Armoury Chest and saved retainer, glamour dresser and armoire checks for this character; **Missing** means absent from the checked storage.
- Duplicate items require enough physical copies. One ring cannot satisfy two ring slots. The side on which a matching ring is worn does not matter.
- HQ and NQ copies both count. Food, relic stat allocations, and item quality are not validated.
- Materia is compared by item ID (type and grade), with duplicates counted separately. Order does not matter, and all five meld slots are checked. Exact matches require no missing or extra materia.
- Hover the Materia column to see expected, current, missing and extra melds. Loose materia does not count as melded gear. The matcher allocates owned copies across the set to prefer correct melds, including duplicate rings.
- Existing sets from 0.1.0 have unknown meld targets until you click **Refresh from link**. A missing or unreadable materia list is never shown as correct. An explicit empty target expects no materia.
- Matching direct gear drops receive a soft blue icon glow in the standard Need/Greed window. Loot always checks all saved jobs, even when farming other jobs' gear with Greed and when the checklist is closed. The current-job-only loot option has been removed, including its configuration field and matcher filtering. Old saved values are ignored; the checklist's job filtering is unchanged.
- Wanted missing loot also receives a blue **!** badge over the icon. Matching selected item names and list-row names (where shown) turn blue. Name colors restore when the item no longer qualifies, highlighting is disabled, the addon finalizes or GearScout unloads.
- Version 0.5.1 enlarges the complete badge by 50% and removes embedded native rarity color macros while a matching name is blue. The original encoded text and color are restored afterward; unrelated formatting and icons are preserved. Nested name components and previews without a selected-item index are supported.
- The glow requires an item to be wanted by a saved set and missing from live inventory and the character's saved storage checks. Owned gear suppresses it regardless of materia; a set needing two identical rings still requires two copies, while alternative saved sets can reuse one owned copy. Ownership refreshes once per second with the checklist closed while highlighting is enabled. Unknown live inventory suppresses the glow.
- It is shown only for available Need/Greed rolls, and does not automate rolling. Coffers and exchange tokens are not mapped to their rewards.
- Open a summoning bell to the list and use **Saved storage checks → Scan all retainers** to visit each available inventory in turn. Progress and Stop controls appear while running. Individually opened retainer inventories, the glamour dresser and the armoire automatically save once fully loaded, even with the checklist closed. Transfers trigger fresh saves; **Scan open storage** and **Forget** remain available. Retainer bags and equipped gear are independent sources; open equipment separately if not loaded with bags. Selling/market listings are excluded. Dresser data includes expanded outfit pieces; glamour plates are not physical ownership.
- Open each chocobo saddlebag tab to save its loaded contents. Standard and premium stores are independent per-character sources; both pages must be loaded before replacing a check. Opening, transfers and closing use the same automatic save triggers as other storage. Gear and attached materia count towards ownership; loose saddlebag materia appears in the planner's separate Saddlebags column and must be moved into bags before melding.
- Saved checks are last-known contents. Reopen storage after changes made with the plugin disabled; stale checks can count removed items or duplicate a transferred copy. Unvisited stores and other characters are excluded. Retainer/saddlebag materia and quality are saved; dresser and armoire contents have no melds.
- Custom/negative XIVGear item IDs are unsupported. Invalid imports report an error and leave the previous saved sets intact.
- Saved target sets are shared by the plugin configuration. Live inventory is read from the current character; storage checks persist locally and are isolated by character content ID and source key.

## Build from source

Requires .NET 10 SDK and Dalamud API 15 assemblies installed by XIVLauncher. No need to compile Dalamud itself. From this directory run:

```powershell
.\build.ps1
```

The script uses `DALAMUD_HOME` when set, otherwise looks for the developer assemblies or the newest numbered Dalamud installation. Build output is `bin/Release/GearScout.dll`, with its generated manifest alongside it. Game/Dalamud updates may require rebuilding or updating the SDK/API use. If using a custom launcher installation, set `DALAMUD_HOME` to its Dalamud assembly folder first.

Run the importer and ownership checks:

```powershell
dotnet run --project Tests/GearScout.Tests.csproj
# Also check the supplied example against the live XIVGear API:
dotnet run --project Tests/GearScout.Tests.csproj -- --live
```

## Implementation and references

`Plugin.cs` handles lifecycle and framework-thread updates. `MainWindow.cs` draws the UI. `InventoryReader.cs` uses Dalamud's inventory service. `XivGearImporter.cs` fetches and parses sets without game access. `Models.cs` contains copy-aware matching. HTTP work is asynchronous; game access and configuration changes run on the framework thread. Importing sends the supplied link to XIVGear's public API; no character or inventory data is sent.

`MeldPlanner.cs` builds legal ordered actions and exact geometric-attempt convolutions. It preserves the longest feasible prefix, enumerates at most five remaining materia, and minimizes expected attempts among legal sequences. Per-type quantile thresholds use the nth root of the requested whole-plan confidence; the product of independent type CDFs gives the available-stock completion chance. Truncated distribution tails are not renormalized, keeping estimates conservative. Retrieval refunds are displayed separately. `MeldData.cs` reads installed Item/Materia/MateriaGrade/BaseParam/ItemLevel sheets, including slot/quality/grade rules and slot/role-modified stat caps. `MeldGuide.cs` observes exact copy locations and expected meld states, measures negative bag-count deltas conservatively and stops at session/type limits or invalid transitions. `MeldingWindow.cs` and `MateriaTargetEditor.cs` provide fixed-size planning and target selection windows.

`AutomaticMeldSession.cs` is a pure state machine driving window/category/gear/materia/dialog/result phases. It reserves one authorization before a meld dialog is requested, verifies expected before/after gear states and single-unit consumption, and waits at least two seconds plus 750 ms of stable, non-busy results before committing an outcome. Unacknowledged operations time out after 25 seconds without blind resubmission. `AutomaticMeldController.cs` adapts that state machine to AgentMateriaAttach and native callbacks: category event 0/0, gear 0/1, materia 0/2, retrieval 4, and single-attempt confirmation dialogs. It validates exact live inventory pointers, quality, ordered melds, native selected indices, allowed socket rules and the dialog's success percentage before confirming. Target changes are checked on the framework thread before issuing another command. Native callback contracts were checked against public ECommons/YesAlready helpers and AutoMeld's agent usage; the orchestration/state machine is implemented independently.

Socketless gear exits planning before validating potentially non-materia relic fields. `MeldEligibility.cs` provides skip reasons and live-first copy allocation. Guidance receives only selected valid live pieces needing work. The native window opener executes GeneralAction 13 when available, otherwise 12, checks action status/acceptance and verifies MateriaAttach visibility with a three-second timeout. It reports blocked/failed openings instead of silently calling the agent's Show method.

Optional installed-game data regression checks (PowerShell 7, run the build first): `dotnet run --project NativeTextChecks/NativeTextChecks.csproj -- --game-data D:/Games/FF14/game/sqpack`. These read game files only and do not perform native in-game actions.

`WantedItemTracker.cs` tracks first-observed ownership and chest/item identities per character. A silent inventory baseline and remembered live/saved ownership suppress old-item acquisition notices; active/recent storage transfers are silent. Eligible drops use per-set missing-item rules and a bounded history of 4096 chest entries, independent of native window visibility and the glow toggle. `Plugin.cs` reads native loot on inventory refresh and uses `IChatGui.Print` for local messages containing item names and matching set/job labels. Loading/unknown inventory requires a new silent ownership baseline. Chat notification failures do not invalidate the ownership snapshot.

`LootMatcher.cs` implements job scope, item-ID normalization and conservative roll-eligibility matching. `LootHighlighter.cs` reads the current NeedGreed list and live loot slots on each draw, finds visible item-icon bounds and draws the soft blue ImGui outline and punctuation badge without adding input handlers. A NeedGreed PreDraw listener colors exact, localized matching name text. `LootNameFormatting.cs` removes inline rarity foreground/glow payloads so they cannot override the blue base color, retaining other payloads. It calls native SetText to invalidate the layout cache. Original encoded text and colors restore through traversal of currently live nodes, only when those fields still match GearScout's applied values. PreFinalize and disposal restore remaining fields and unregister listeners. The icon overlays share ImGui's foreground layering relative to native windows. Native name coloring and badge appearance still need live visual verification.

`StorageScanner.cs` reads opened, loaded sources; retainer identity must agree with ItemOrderModule and every container in a snapshot must be loaded after a short stabilization delay. Dresser reads use the complete agent item array after population, and armoire reads require loaded Cabinet state. Addon setup/finalization and inventory-change events schedule fresh checks, with a 150 ms transfer debounce and a three-second identity-bound grace period for recently closed stores. Complete opening and transfer checks force a new timestamp/save; background unchanged checks refresh at most every 30 seconds. `StorageCache.cs` replaces complete source snapshots and combines them with live inventory for the current character. Unavailable native data keeps the previous saved snapshot. Save failures retry and are surfaced in the storage status.

`RetainerScanSession.cs` is a tested state machine for list → menu → loaded/saved inventory → menu → list. `RetainerScanController.cs` resolves available roster rows to stable retainer IDs, uses localized Addon-sheet menu labels, and issues only selection, inventory-open, inventory-hide and Quit navigation actions. The next retainer cannot start before the previous snapshot has persisted. Stop, character/loading changes, a 30-second phase timeout, unexpected dialogs and mismatched ready retainer identities stop further callbacks. Native navigation still needs in-game acceptance testing.

`RetainerMenuMatching.cs` matches the literal localized prefix before a template's first dynamic macro, allowing the rendered slots-filled counter to change. Static labels such as Quit require an exact match; empty prefixes, missing entries and ambiguous matches are rejected. Native regression checks include the installed game's English Addon row 2378 bytes and the reported zero-slots menu.

`GearCatalog.cs` indexes local game rows in small framework-thread batches. `GearSearch.cs` implements job/slot filters, ranked token/ID searches, ring constraints and independent edit drafts. `SetEditorWindow.cs` draws slot buttons and the searchable picker; search results are cached per query and clipped for long lists. Local saves replace a set by ID and roll back in-memory changes if persistence fails. Local sets have an empty SourceUrl, so XIVGear refresh operations do not replace them.
